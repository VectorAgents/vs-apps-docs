What each claim in these docs rests on. A ticket or spec named below without a link rests on a `.scratch/` folder that no longer exists, so the claim cannot be traced further.

The sections below follow the page folders: Why Vector Space is under `docs/vector-space/`. Quickstart, Guides, How a Vector App works and Why Vector Apps are under `docs/vector-apps/`. App definition, Reference and SDK overview are under `docs/sdk/`. The Entry page is `docs/index.mdx`.

## SDK gaps

- The SDK declares no `engines` field. The quickstart Prerequisites name Node.js 22.12 or later. The scaffold CLI (`@vectoragents/create-app`) needs Node.js `>=20.19` and Vite 8 needs `^20.19.0 || >=22.12.0`, so 22.12 is the one floor that holds for both with no exception (review ticket 11, item 5). Vite 8 accepts every LTS from 22.12, and the starter CI tests `lts/*`.
- The dev route shapes rest on the framework-free dev routes of the app platform (`server/app-platform/dev-issuer/` and `server/dev-issuer/`) and the harness component (`react/harness/`), all in the installed 0.5.0 dist.

## Observed on a Vector Space of the 0.5.0 era

Review tickets 18 to 21 drove the real stack through the browser and the terminal: a Vector Space at `vector-spaces` commit `cb4c39e10` (migration 184, cloned database) and the app on SDK 0.5.0 (`leads-app` start, node server, except the connector check on Nest). The pages use the labels of Vector Space `main` where the two differ. A hosted Vector Space was not run.

- Call a model (ticket 18): with no model set the route answered `409` with the body `No model is set for the "lead-summary" slot on this space`. With a model set it answered `200` and `{"summary":"..."}` after `waiting for the model` for several seconds. A model needs an Anthropic provider on the organization (**Settings**, **Organization**, **Providers**, **AI**, **Add provider**), then **Set** gives the toast `Model saved`. The user token exists only in page memory, so `curl` cannot send a valid one, and the page shows the result through a `fetchSummary()` of about eight lines. Without a token the route answered `401`.
- Call Vector Space (ticket 19): the connectors route answered `200 []` (a space with no connector). The agent route answered `200 {"threadId":"..."}` and **Sessions** listed a new session titled with the message, but only after the route sat above the `platform.fetch` line of `main.ts`. In the starter order it answered `500` with `readJsonBody(req)` returning `null`. No cause is claimed. The reply text was not read.
- Connector events (ticket 20): delivery, the app log line and the **Events** tab worked as the guide says. A `REST` connector accepts no inbound webhooks, so the slot uses `provider: 'APOLLO'`. A reply that Vector Space refuses with `404` or `403` is final (`1 failed`, **Redeliver**, no second attempt). A `500` was retried three times, about 5 and 10 seconds apart (`3 failed`). Not observed: a successful reply, the `result.status >= 400` branch and a resend that succeeds.
- A2A (ticket 21): the card and the `401` held. Staff **Check for updates**, **Review update**, **Apply**, then a space admin **Add to agent graph**, then **Publish All** in **Agent Studio**, then a chat message that names the agent gave `Routed to specialist agent`. With `handleA2aRoute` after `platform.fetch` the chat showed `Invalid response Content-Type for SSE stream` and the body was `null`. With the route above `platform.fetch` the call worked. No cause is claimed.
- Remove and add again (ticket 18): the slot resets (`No model set yet.`). The model choice, the connector choice, the shares and the consents of a binding do not survive a re-add (`BINDINGS.md`, `provisioning.service.ts` in `vector-spaces`).
- Local-only details of these runs are not published: Vector Space tiers and their start commands, `EGRESS_PRIVATE_HOSTS`, ports, the cloned database and the scratch logging.
